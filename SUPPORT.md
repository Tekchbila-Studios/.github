# Support

Where to take a question, so it reaches someone who can answer it.

| You want to... | Go here |
|---|---|
| Report a bug in a project | Open an issue **on that project's repository** |
| Ask how something works, or propose an idea | Open a discussion, or an issue if the repo has none |
| Report a security vulnerability | [SECURITY.md](SECURITY.md) — **not** a public issue |
| Ask about Infragr.am the service — pricing, accounts, billing | <https://infragr.am>, or <contact@infragr.am> |

## Getting a useful answer faster

Include the version or commit you're on, what you expected, what happened, and
the exact error text rather than a paraphrase of it. If it involves a Terraform
plan, the provider and Terraform versions matter more than anything else in the
report.

A minimal reproduction is worth more than a long description. If you can get the
failure down to a handful of resources, the fix usually follows within the day.

## What we can't promise

This is a small studio. Issues are read; not all of them get an immediate reply,
and questions that are really about using Terraform rather than about our tools
may get a short pointer instead of a full answer.

Security reports are the exception — those are always prioritised, on the
timeline in [SECURITY.md](SECURITY.md).
